Live Map Checker の v1 を作ります。まだコードは書かず、Planモードで設計と実装計画を作ってください。

## 前提資料（最初に必ず読む）

- `docs/requirements.md`: 要件定義書（確定）
- `docs/mockup/`: UIモックアップ（確定）。`README.md` に画面一覧があります。見た目はこれに合わせます。

## 技術構成（決定済み）

- TanStack Start（TypeScript）＋ Cloudflare Workers ＋ D1 ＋ Drizzle
- Tailwind CSS v4 ＋ shadcn/ui
- 定期実行は Cloudflare Cron Triggers、AIは Claude API（Web検索ツール）。AIの提供元は差し替え可能にする
- GitHub ＋ GitHub Actions、開発環境は WSL（Ubuntu）
- ライブラリの使い方は、Context7 で最新のドキュメントを確認してから決めてください

## 計画に含めてほしいこと

1. **プロジェクトの初期構成**: 作成コマンド、ディレクトリ構成、CLAUDE.md に書く内容、lint／format（Hooks で自動実行）
2. **DB設計**: 地方・県・会場・公演・情報源・AI検索のキャッシュ・取得ログなどのテーブルと、初期データ（10会場）の入れ方
3. **データ取得**
   - 会場ごとのスクレイピングの作り（会場ごとの取得ルールを差し替えられる形）
   - 各会場の利用規約と `robots.txt` の確認手順。禁止されている会場はAI検索のみにする
   - 失敗の検知と記録
4. **AIによる補完検索**: 呼び出しのタイミング、24時間キャッシュ、出典URLを実際に取得して「アーティスト名と日付」が載っているかを確かめる検証、費用の上限の設け方
5. **ライブ判定**: 学会・展示会・スポーツなどを除外する方法（ルールベース／AI／併用の比較と推奨）
6. **画面とルーティング**: スマホとPCの両レイアウト、日本地図のデータ（タイル配置で実装するか）、ダークモードを初期値にしたテーマ切り替え、下部ナビ（長押しスライド）とPCの左ナビ
7. **お気に入り**: ブラウザへの保存、アーティスト名の表記ゆれの正規化、v2でアカウントへ引き継ぐための設計
8. **テストと品質**: 単体テスト、E2Eテストの範囲、`/code-review` と `/security-review` を使うタイミング
9. **CI/CD とデプロイ**: GitHub Actions、PRごとのプレビュー環境、本番デプロイ、シークレット（APIキー）の管理
10. **スケジュール**: 2026年11月中の v1 公開に向けた、機能ごとの実装順（1機能 = 1ブランチ = 1PR）
