# Live Map Checker 要件定義書

- 作成日: 2026-10-23
- 対象バージョン: v1（2026年11月中に公開）
- ステータス: ドラフト（Planモードでの設計前）

## 1. 概要

アーティストのライブを、**アーティストからではなく「場所（会場）」から探す** Webアプリ。

### 背景・課題

- 地方に住んでいると、ライブ情報を知っても「遠くて行けない」と分かって落胆することが多い。
- 最初から「行ける会場」で検索できれば、この落胆が起きない。
- 場所から探すことで「このアーティストが近くに来るなら行ってみよう」という新しい出会いも生まれる。

### 想定ユーザー

- ライブが好きな人全般。
- 主な使い方: 調べたいときにWebアプリを開き、近くの会場のライブを確認する。

## 2. スコープ

### v1（2026年11月中に公開）

| # | 機能 | 内容 |
|---|---|---|
| F1 | 日本地図トップ | 日本地図を表示。情報を登録済みの地方（v1は**九州・関西**）だけ色付きで選択可能 |
| F2 | 地方 → 県の選択 | 地方を選ぶと、情報登録済みの県が選べる |
| F3 | 会場一覧 | 県を選ぶと、その県の登録会場が一覧で表示される |
| F4 | ライブ一覧 | 会場を選ぶと、**アーティストのライブだけ**を日付順に表示（学会・講演・展示会・スポーツ等は除外） |
| F5 | お気に入り照合 | 「お気に入りアーティストがこの会場に来るか」を確認するボタン |
| F6 | お気に入り管理 | お気に入りアーティストの登録・削除。**ブラウザに保存**（ログイン不要） |
| F7 | 情報の自動取得 | 対象会場の公式サイトから公演情報を定期取得（スクレイピング） |
| F8 | AIによる補完検索 | 自動取得に失敗した会場・情報がない会場は、閲覧時にAIがWeb検索して補完 |
| F9 | 出典表示 | AIで取得した公演には「AIによる検索」ラベルと出典リンクを表示 |
| F10 | ダークモード | **初期値はダークモード**。アカウント画面の「テーマ」で「システム／ライト／ダーク」を選べる（選択はブラウザに保存） |
| F11 | アカウント画面 | 下部ナビの「アカウント」から開く。v1はゲスト表示（ログインボタンはv2予定）＋テーマ設定＋規約・プライバシーポリシー・情報の取得方法・お問い合わせへのリンク |

### v2（v1公開後）

- ログイン機能（入口は画面下部ナビの「アカウント」タブ。v1では配置のみで、押しても何も起きない。ログイン後はアバター表示になり、押すとアカウント画面（お気に入り会場・通知設定・ログアウト）を開く。ハンバーガーメニューは使わない）
- お気に入りの**会場**と**アーティスト**の登録（v1のブラウザ保存分をアカウントへ引き継ぐ）
- 「お気に入り会場 × お気に入りアーティスト」が一致したら通知（方式は v2 設計時に決定: メール / Web Push など）
- 対象会場・地方の拡大

### 対象外（v1ではやらない）

- チケットの販売・決済
- ユーザー投稿による公演情報の登録
- ネイティブアプリ（スマホアプリ）

## 3. 画面構成（v1）

1. **トップ**: 日本地図。九州・関西に色が付き、タップ／クリックで選択（地図の下に地方ボタンは置かない）
2. **地方**: 県の選択（地図のタップのみ。下部の県リストは置かない）
3. **県**: 会場一覧
4. **会場**: ライブ一覧。表示の切り替え
   - 「すべてのライブ」
   - 「お気に入りが来るか」
5. **お気に入り**: アーティストの登録・削除
6. **アカウント・設定**: ゲスト／ログイン後の表示、テーマ設定、通知設定（v2）、規約などのリンク

画面の詳細はUIモックアップで確定させる（→ 8章）。

### PC版のレイアウト（幅1024px以上を目安）

| 部分 | スマホ版 | PC版 |
|---|---|---|
| ナビゲーション | 画面下部のタブ（長押しでスライド） | 画面左端の縦ナビ（ガラス風）。ホバーでインジケーターが移動する |
| 地図と一覧 | 地図 → 地方 → 県 → 会場と画面が切り替わる | 左に大きな地図、右に一覧パネル。地方を選ぶと右に県と会場の一覧が出る（画面遷移なし） |
| 会場画面 | 縦1列 | 左に会場情報と同じ県のほかの会場、右にライブのカードを複数列で表示 |
| アカウント・設定 | 縦1列 | 中央寄せ（最大幅 880px）、2列のカード |

## 5. データ取得の方式

### 5.1 自動取得（スクレイピング）

- 対象: 4章の各会場の公式スケジュールページ。
- 頻度: 1日1回（Cloudflare Cron Triggers）。
- 取得結果はDBに保存し、表示はDBから行う。
- **前提条件**: 実装前に各サイトの利用規約と `robots.txt` を確認する。自動取得が禁止されている会場は、AIによる補完検索のみの対象とする。
- サイトのページ構造が変わって取得に失敗した場合は、エラーを記録し、その会場はAIによる補完検索に切り替える。

### 5.2 AIによる補完検索

- 実行タイミング: **ユーザーが会場を開いたとき**に、その場で実行する（自動取得の情報がない、または失敗している会場のみ）。
- 結果は **24時間キャッシュ** し、同じ会場への2回目以降のアクセスでは再検索しない（表示速度と費用の対策）。
- 検索中はローディングを表示する（1回あたり10〜30秒かかる可能性がある）。

### 5.3 AI結果の検証と表示ルール

AIは、存在しない公演を作ったり、古い公演や別種のイベントを返したりすることがあるため、次のルールで表示する。

1. AIには、各公演の**出典URL**を必ず返させる。
2. サーバーが出典URLを実際に取得し、ページ内に**アーティスト名と日付**が含まれているかを確認する。
3. 確認できた公演のみ表示する。確認できなかったものは表示しない。
4. 表示時は「🔍 AIによる検索」ラベルと**出典リンク**を付ける。
5. 自動取得（5.1）による公演にはラベルを付けない。

### 5.4 ライブ判定

- 会場のスケジュールには、学会・講演・展示会・スポーツ（野球、格闘技など）が混在する。
- **アーティストのライブだけ**を表示するため、タイトルや種別から判定する。
- 判定方法（ルールベース / AIによる分類 / その併用）は設計時に決定する。

### 5.5 AIの提供元の切り替え

- 初期: 開発者個人のAPIキー（Claude API）を使う。
- 将来: 大学で利用できるサービスへ切り替える可能性がある。
- そのため、AIを呼び出す部分は**提供元を差し替えられる設計**にする。キーはコードに含めず、Cloudflareのシークレットで管理する。
- 代替案: ブラウザ内LLM（Chrome内蔵AI、WebLLM等）。ただしWeb検索はできないため、「サーバーが取得した文章からの情報抽出」に用途を限る。

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| 対応端末 | **PCとスマホの両方**（レスポンシブ）。地図はタップ操作にも対応 |
| 表示速度 | 自動取得済みの会場は即時に表示。AI検索は初回のみ待ち時間あり |
| 費用 | 月1,000円程度まで（AIの利用料を含む） |
| 可用性 | 個人運営のため、厳密なSLAは設けない |
| セキュリティ | APIキーなどの秘密情報をリポジトリに含めない |
| 法令・規約 | スクレイピング対象サイトの規約・`robots.txt` を遵守する |

## 8. デザイン方針

- **雰囲気**: ポップで、モダンなガラス風（グラスモーフィズム）。
- **既定のテーマ**: ダークモード（背景 `#0E1A20` に、ミント・紫・ティールの柔らかい光を重ねる）。
- **ガラス風の部品**: ヘッダー・カード・ボタンは半透明の面＋背景ぼかし（`backdrop-filter: blur`）＋薄い白の縁取り。
- **ヘッダー**: 戻るボタンとパンくずリストのみ（テーマ切り替えはアカウント画面へ移動）。パンくずリストが長いときは「…」で省略する。
- **下部ナビ（Google・LINE風のボトムナビ）**: 全画面の下に固定。「マップ」「お気に入り」「アカウント」の3タブで、アイコン＋ラベル。
  - 現在のタブは、ガラスの選択インジケーター（ミント色）で示す。
  - **タップ**でタブを移動する。
  - **長押し（約0.25秒）**でインジケーターが少し浮き上がり、指に合わせて左右にスライドできる。指を離すと一番近いタブに吸い付いて移動する。
  - 移動時は少し弾むアニメーションにする。
- **イベントカードのリンク**: 「詳細 ↗」のみ（チケット販売サイトにはAPIがないため、会場公式の公演ページへ飛ばす）。
- **角丸**: 控えめにする（ヘッダー 18px、カード 16〜20px、ボタン 10〜12px、バッジ 8px）。
- **地図のタイル**: 情報がある地方・県は不透明のミント／ティールで光らせ、準備中はガラス風の薄いタイルにする。
- **参考サイト**: [Trailblaze Asset Management](https://trailblazeam.com/)
  - ライトモードの背景は、温かみのあるオフホワイト（`#EAE7D6` 付近）
  - 浮いているように見えるヘッダー
  - スクロールに合わせて要素が現れるアニメーション（GSAP ScrollTrigger）
  - 横に自動で流れるカルーセル
  - 「01, 02…」の番号付きセクション、ゆったりした余白
- **メインカラー**（ティール系のグラデーション）:

| 用途の目安 | 色 |
|---|---|
| 明るいアクセント | `#39EAC3` |
| メイン | `#00C8BD` |
| | `#00A7AF` |
| | `#118698` |
| | `#2A667A` |
| 文字・暗い面 | `#2F4858` |

- 差し色の候補: ティールから青・紫へ伸ばしたグラデーション（`#39EAC3` → `#00C8BD` → `#00B3D8` → `#0093D1` → `#4372B5` → `#625295` 付近）。
- **UIモックアップ**: [Live Map Checker UIモックアップ](https://claude.ai/artifact/2Jbf75sDTdHTeihfgAASWw)（主要5画面＋ライトモード版）。実装はこの見た目に合わせる。
